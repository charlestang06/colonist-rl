# Bounded staged Colonist execution

The approved second adapter wave follows the independently reviewed UI evidence contracts. Learning remains primary. This wave supplies a small explicit executor for placement and incoming willingness, then the minimum focused-drag activation path. It does not implement a generic workflow engine.

## Global constraints

- Work only in `/private/tmp/colonist-swarm-bxz1k39_/adapter`; original repository is read-only. Baseline is `47a28d93ed1a9955771d4a740b718d152c932ffe`.
- Preserve Python >=3.11, shared Observation/Action/schema version 1, policy action kinds, simulator atomic trades, legacy module identities, and the existing BrowserAdapter.execute and BrowserTransport APIs.
- No live Colonist connection, screenshot/photo recognition, hidden state, private APIs, network installation, ledger mutation, semantic-history guessing, CLI/training changes, or development-card/robber sequence support.
- Use original `.venv/bin/python` and `.venv/bin/ruff` read-only with workspace `PYTHONPATH=src` and `PYTHONDONTWRITEBYTECODE=1`; no uv sync.
- All replay fixtures are explicitly synthetic models grounded in the saved controls; images are snapshots, not recorded transitions. Transport tests use an injected public Page/Mouse double or opt-in loopback HTML only.
- Every gesture is issued at most once for its established stage. Set the review lock before the gesture; preserve it after uncertain outcomes or interruption. Never blindly retry a gesture.
- Runtime/source ownership is limited to Colonist adapter modules plus their new tests and adapter docs; shared contracts, simulator, beliefs, policy, training, CLI, and board remain untouched.

## Public boundary

Create `adapters/colonist/staged_execution.py`, leaving `execution.py` unchanged. Add frozen `LocatedUIControl(control: UIControl, point: Point)` and `StagedCapture(capture: CaptureObservation, ui: UIState, controls: tuple[LocatedUIControl,...] = ())`, plus `StagedCaptureReader.read(screenshot: bytes) -> StagedCapture`. Detach coordinate/control inputs, reject nonfinite/negative/bool coordinates and duplicate control IDs, and require each located control's revision equal its UI revision. UI observation version must equal capture.observation.context.version. Supplied verified capture metadata vouches for the complete screenshot's game/UI/coordinate evidence, not just game fields. When capture supplies a screenshot SHA-256, the executor checks it against the bytes; absent digest is allowed under the existing injected-reader trust contract.

Expose `StagedBrowserAdapter(*, calibration, transport, reader, enabled=False, authorized=False, min_confidence=0.95, max_captures=8, poll_interval=0.05, wait=time.sleep)`. `max_captures` is a positive integer including the initial capture and all stages; `poll_interval` is finite in [0,1]. There are at most two placement clicks, one incoming acceptance click, or (after Task 2) one activation drag plus the two placement clicks. Wait between unchanged/unstable polls, never before an action retry. An operation must reserve at least one remaining capture before issuing another gesture. Count bounds apply to calls that return; synchronous transport calls are not promised a hard wall-clock timeout.

`execute(observation: Observation, action: Action, *, expected_revision: int, row_id: str | None = None) -> UIExecutionResult` supports canonical `Action('BUILD_SETTLEMENT'/'BUILD_CITY'/'BUILD_ROAD', target=...)` and canonical incoming `Action('ACCEPT_TRADE', offer_id=...)`. Well-formed unsupported kinds/shapes return blocked before gestures. Malformed argument types or Action payloads raise TypeError/ValueError before transport I/O; no UIExecutionResult is constructed around an invalid Action. It exposes `needs_review: bool`. No reset/retry API is added. Permission absence raises PermissionError; invalid constructor configuration raises ValueError/TypeError. Safe preflight failures produce blocked with a reason and no gesture. Any ordinary exception or unexpected post-gesture evidence produces ambiguous with a reason and retains needs_review. BaseException interruption propagates but leaves the pre-set lock. An already-locked instance blocks without further transport calls. A known committed placement or known pending willingness clears the lock.

Initial checks require exact current Observation equality, matching expected UI revision, verified/stable/confident capture, valid board/calibration, legal action and current player as actor, canonical action shape, and no incompatible active dialog/selection. Selected action may initially be None for geometry placement; incoming response must already be selected as required by the reviewed binding validator. Use existing `validate_confirmation`, `validate_trade_response`, and `validate_acknowledgement` to validate applicable stages rather than inventing looser bindings. Reuse the existing `_expected_transition` for supported placement effects, adding same player/board/rules and strictly later game-version guards; do not duplicate its geometry logic or broaden it.

## Task 1 placement and willingness paths

Placement starts only when both capture.target_mode and ui.active_tool equal the action kind. An initial unrelated selected action, dialog, or confirmation blocks; a pre-existing confirmation can be consumed only when exactly bound to this selected action/current revision through validate_confirmation. Otherwise select the exact calibrated target once. Poll bounded captures: unchanged evidence can wait; a newer UI with exactly unchanged game Observation and exact selected action/confirmation permits one confirmation click. Resolve coordinates by equality of the complete UIControl in the current StagedCapture; control ID alone never binds a gesture. Re-read evidence is the boundary between each gesture. If the first target click directly commits a verified placement, return committed without a confirmation click. After confirmation, only verified placement commitment succeeds. A vanished dialog, higher version alone, another target, changed game state without the exact placement, or stale/revised control is insufficient.

Post-gesture snapshots must preserve player/board/rules. Repeated equal UI/game evidence may be polled; unstable but verified/confident capture may be polled without gestures. For revision consistency, payload means Observation, UIState, target_mode, and located controls; screenshot bytes/hash and confidence/stability metadata are not payload identity, so an animation or unstable-to-stable capture can retain a revision. A backwards revision, changed semantic payload under the same UI revision, lower game version, low confidence, unverified or malformed evidence, wrong phase/target/offer, or unexpected game change is ambiguous immediately. A valid committed placement requires newer UI revision, later game version, and action-specific visible board change. Its UIExecutionResult includes the refreshed Observation and concrete evidence strings naming action kind/target/actor/version; no predicted resource accounting.

Incoming acceptance requires TRADE_RESPONSE context, exact shared offer/recipient/action, fundability via validate_trade_offer, explicit row_id and exact current row/control through validate_trade_response. A pre-existing own willing/rejected marker blocks without a duplicate click. Click the exact response once. Return pending only after strictly newer UI revision, exactly unchanged complete Observation, same row identity/offer/proposer/terms at the new revision, and that player's willing marker; call validate_acknowledgement and attach a visible-marker evidence string. A disappearing/changed row, selected different partner, hand change, or cancellation is ambiguous for this bounded operation, never committed. Future trade completion/cancellation tracking is unsupported.

## Task 2 focused drag activation

Extend PlaywrightTransport with additive `drag(start_x, start_y, end_x, end_y, *, steps=10) -> None`; keep existing BrowserTransport unchanged and define an extended `DragBrowserTransport` protocol in staged_execution.py. Validate finite nonnegative real non-bool coordinates and positive non-bool integer steps. Use only public Mouse.move/down/move/up methods. Capture the starting allowed origin; recheck connection and same origin before/after each mouse operation. If a partial drag fails, attempt release only while still connected on the original allowed origin, preserve the original exception, and do not continue a move/drop on a changed origin. Preserve all prior transport guards. This does not claim a hard individual mouse-call timeout.

For BUILD_SETTLEMENT and BUILD_CITY only, if the build mode is not active, the supplied capture may provide exactly one located UIControl with gesture='drag', complete canonical action, current revision, no row/partner, and control_id equal ui.focused_control. The selected action must equal this action. Require no confirmation/dialog and an available drag method. Drag from its verified point to the calibrated target once. Do not add a focus click: focus acquisition remains outside this slice. Poll until verified unchanged-game evidence at a strictly newer revision establishes both capture.target_mode and ui.active_tool equal action.kind, same selected action, and no unexpected confirmation/dialog. Then reuse Task 1's placement path within the same global capture budget. No-effect drag, tooltip without established mode, or ambiguous post-drag state must not trigger another drag or target click. BUILD_ROAD starts in verified active mode; drag activation for it is unsupported.

## Acceptance and scope

Offline fixtures cover setup target/confirmation, ordinary direct placement, pre-existing exact confirmation, delayed/unstable render, same-kind wrong target, moved/stale control binding, interruption after each issued gesture, timeout, exact incoming willingness with unchanged hand, wrong/changed/expired/simultaneous offer rows, already-willing duplicate prevention, and focused drag success/failure/tooltip paths. Test the exact ordered gesture log and counts, lock outcomes, result status/evidence, unchanged supplied observations, and untouched legacy behavior. New imports do not start browser sessions. The existing browser API tests plus a local-only drag test establish transport boundaries; no live game is claimed.

Unsupported after this wave: focus acquisition, keyboard, Knight/Monopoly/robber/YOP/Road Building/discard sequences, bank/outgoing finalization, incoming rejection edits, acceptance completion/cancellation monitoring, automatic UI reading, stable live row IDs, ledger/history integration, and arbitrary photographs. Existing BrowserAdapter.execute remains available unchanged.
