Frozen on 2026-11-06 before v2 implementation and before any v2 probe or game. This study starts from the stopped v1 branch commit ed80fc1 in a separate linked worktree. ## Mechanical hypothesis

The [v1 timing diagnosis](../runs/public-round-forecast-2026-11-06/train-probe/timing-profile.md) located most wrapper time in ten scalar Python four-roll dynamic-programming calls per five-root view, including 202,740 tuple-generator iterations in a representative profiled view. The unchanged parent planner call was much smaller. V2 will enumerate the exact 11^4 ordered dice-total sequences once, use their integer 2d6 multiplicity products, and evaluate all original legal END/bank roots and public bank lower/upper endpoint scenarios in arrays of at most 16 scenarios per batch. This is an algorithmic throughput hypothesis, not a new decision feature.

For each roll and resource, v2 applies the same fixed-board public demand and bank-shortage rule as v1: if the current endpoint bank can pay total public demand, subtract it and credit own production; otherwise credit none. Seven yields no production. Own hand is clipped at active point-recipe thresholds, at most (1,1,1,2,3). The success event is the same current-geometry city-or-connected-settlement affordability after four rolls. Integer favorable weight out of 36^4 and floor(50,000,000 × mass / 36^4) must exactly match the untouched v1 scalar point_affordability_mass for every scenario. No RNG, hidden state, opponent action model, or future menu is added. Public bank endpoints remain sensitivity scenarios, not mathematical probability bounds.

Raw and static arms are unchanged. The forecast wrapper still calls the raw planner once, then only after the same END fallback compares the identical original END/bank roots and projections. It still requires the same bank trade to win at both endpoint scenarios by 10,000,000 score units and allows at most one anticipatory trade per own turn. Root object identity, action order, score rounding, diagnostic status, and raw search work must remain equal to v1 on equivalent observations. NumPy is available in the pinned runtime and the exact sequence table is cached; scenario arrays are processed in chunks of at most 16 to bound temporary memory.

Wrapper-level tests compare selected root identity, score and diagnostics to a scalar reference on fixed synthetic views, including endpoint disagreement and same-turn second-call guard. Verify one parent call per decision and original Action object identity. Run the relevant existing suite and Ruff on new/changed implementation files. Commit and record the exact v2 source-tree SHA-256 before running the v2 TRAIN probe. Any equivalence failure stops before games.
