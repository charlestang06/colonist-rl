# Public one-round production option: frozen development protocol

Frozen before implementation, TRAIN capture, and game screens on 2026-11-06. Base commit: 7d11170. The branch is isolated; raw planner source and the Original checkout are unchanged.

## Question and arms

Can a one-round public production forecast choose a better bank trade versus ending the current turn after the raw planner has returned its ordinary END fallback? This tests a conditional point-build option that the existing static hand-balance and production score does not calculate. An empty-beam search stop is a scope signal, not evidence that raw made a bad decision.

All arms use the unchanged PublicTurnPlannerPolicy with max_depth=6, max_nodes=2048, beam_width=24, max_geometry_visits=100000, seed=11, prune_invalid_future=true, gain_margin_micro=250000. No evaluator, purchase wrapper, or opponent trade offers. The three arms are:

1. raw: parent planner only;
2. static: parent planner plus a bank-versus-END root comparison using the existing static _score;
3. forecast: identical parent call, root set, projections, root ordering, and threshold as static, adding 50,000,000 times forecast point-affordability probability to each candidate score.

Both wrappers run only when the parent selects an original END_TURN root with reason insufficient_gain and its search_stop is empty_beam or depth_limit, in a standard supported own rolled turn. They enumerate exactly the current legal END_TURN and MARITIME_TRADE root objects, require one END, project each via the existing _root_transition, and abort the override if any eligible root fails validation. They never alter the parent beam, depth, nodes, geometry work, or fallback selection. Current legal point builds and all other parent decisions remain raw. Each wrapper chooses the highest-scoring bank root only if it exceeds END by at least 10,000,000 score units. This margin is one tenth of the existing 100,000,000 point unit; a trade needs a material score gain. Tie order is score, then original root index. A wrapper may initiate at most one bank trade in one own turn; after that it delegates all decisions in that turn to raw, so anticipatory trading cannot loop. It returns the original legal action object and its root index.

## Forecast definition

The option event is: after the fourth roll, current hand plus credited production affords at least one city or a connected settlement, provided the player's public piece stock and current fixed geometry allow it. The four rolls represent the next three opponents' rolls and the player's next roll in a four-player game. Each is an independent 2d6 roll with exact multiplicities 1,2,3,4,5,6,5,4,3,2,1 for totals 2 through 12. A 7 produces no resources. This is a public proxy, not a prediction of actual subsequent play.

The current public buildings, robber position, board numbers and sites remain fixed. The model includes all players' public building production and the engine's per-resource bank-shortage rule: if the bank cannot pay the complete public demand for a resource on a roll, nobody receives that resource. It does not model robber movement, discards, theft, development cards, construction, maritime or domestic trades, changed sites, hidden hands, or hidden future randomness beyond the enumerated dice. No live future menu is fabricated. The score asks whether a point build is affordable, not whether the agent will actually build it.

Initial bank lower and upper resource counts come from the public planner's conservative projection, intersected with bounds inferred from player-visible ResourceBelief lower/upper vectors when all player summaries are present and consistent. The actual bank is never read from hidden simulator state. For each root, the bank trade's publicly known give/receive updates both bounds. A deterministic four-roll dynamic program runs once with the lower endpoint and once with the upper endpoint, each time carrying capped own hand and remaining bank stock. Hand counts are capped at the elementwise maximum of the currently possible point recipes, at most (1,1,1,2,3), because larger own counts cannot change the affordability event. Bank counts stay within public supply 0..19. The probability is the exact integer weighted mass of successful roll sequences divided by 36^4; credit is integer floor(50,000,000 × mass / 36^4).

The endpoint scores are sensitivity scenarios, not a guaranteed probability interval: bank exhaustion can make production nonmonotone in its initial stock. The forecast wrapper abstains unless the same original trade root wins under both endpoint scenarios and clears the 10,000,000 END margin in both. If endpoint rankings or threshold decisions differ, it returns raw END. Report this limitation. Static uses the same candidates and threshold with no forecast credit.

## Data roles and fixed gates

TRAIN probe seeds: 138340000 through 138340007 inclusive, four focal seats each, raw versus three H opponents, no offers, 20000 step cap. Capture every executed raw END with at least one legal bank trade and the complete public before Observation, action, board seed, seat, turn and version in a detached JSONL. These are newly generated TRAIN games, disjoint from the archived 13825x/13826x/138295x and learning 138310x work. No screen outcome or hidden state enters action labels. The probe runs the two frozen wrappers offline on each captured before view, in chronological order per game, preserving turn-local intervention memory. It also records parent search diagnostics, score and forecast probabilities for candidate roots, selected root identities, timing and source/input hashes. Full public before views are retained for audit.

Pre-game gates, all required: at least eight forecast-versus-static selected-action changes on at least four distinct TRAIN boards; every selected action is the identical original root object; no anticipatory second trade within a turn; incremental eligible-decision p95 at most 25 ms over a single parent planner call on the pinned local environment; and blind public-only review of the first 12 changes in board/seat/version order finds no clearly destructive trade or missed current point win. If any gate fails, stop before smoke or fresh gameplay. Report denominator and counts rather than a population failure rate. A change is not automatically an improvement.

If all pre-game gates pass, run excluded smoke seed 138349999 with all three arms, four seats, same opponents and cap. Stop if incomplete, invalid, unexpected action identity, second anticipatory trade, or missed immediate win. Then run exactly eight fresh development boards 138350000 through 138350007 inclusive, four seats and all three arms: 96 scheduled games. Capture candidate public steps and follow-through. These seeds are never used as training labels. Advancement requires all 96 games resolved; forecast has at least three more wins out of 32 than raw and at least three more than static; mean focal VP is nonnegative versus each control; no harmful repeated-trade loop or missed immediate win in changed cases; and the first-divergence public follow-through review supports the mechanism. Whole-board bootstrap uncertainty is descriptive. Promotion still needs separately frozen larger fresh confirmation against authentic VF and AB; this development screen cannot establish superiority.

Do not enlarge or retune a failed gate on the same data. Preserve exact manifests, full probe records, analysis, game journals, code/test hashes, and the verdict on this isolated branch. Coordinate multi-board runs with the root and learning coordinator so experiments do not compete for the same local CPU.
